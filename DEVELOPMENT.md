# Development — numodel-bundle

Notes for working on the bundle itself: building, testing and
releasing.  Users of the packages need only the [README](README.md)
and the package manuals.  This file is not shipped to CTAN.

## Build workflow

The bundle is managed with [`l3build`](https://ctan.org/pkg/l3build).
From the bundle root:

```
l3build unpack             # extract .sty / .def files from .dtx
l3build doc                # typeset the three package manuals
l3build check              # run all regression tests (.lvt against .tlg)
l3build install            # copy generated files into TEXMFHOME
l3build clean              # remove generated files
l3build ctan               # build a CTAN-ready zip
```

Single-module variants are available by `cd`-ing into the module
directory and running the same target (still using the shared
`build/` tree at the bundle root).

### Releasing a new version

The single source of truth for the release tag and date lives in
[`tagsetup.lua`](tagsetup.lua) at the bundle root; the bundle
`build.lua` and every module `build.lua` dofile it so a single
`l3build tag` run propagates the values everywhere.  To bump:

```
l3build tag 0.10.0
```

Run it on the release day: the date defaults to today.  From the
bundle root a date option (`-d` / `--date`) is passed on to the
modules in a way they reject ("Too many tags specified"), so the date
cannot be set explicitly there.

(use a pre-release suffix such as `0.10.0-pre` or `1.0.0-rc.1` if
needed — `tagsetup.lua`'s patterns accept them).  This rewrites:

- `\ProvidesFile` / `\ProvidesPackage` / `\ProvidesExplFile` /
  `\ProvidesExplPackage` headers in every `.dtx`
- `Copyright (C) YYYY` lines in every `.ins`
- the version line in the header comment of every shipped `.lua`
  file (`numodel.lua`, `numodel-coach.lua`,
  `numodel-coach-template.lua`)
- the `release_tag` / `release_date` constants in `tagsetup.lua`
  itself, so the next run starts from the freshly-released values

After tagging, hand-edit `CHANGELOG.md` at the bundle root to describe
what changed (changelog content is inherently human-authored, so it
stays manual), write the announcement in `release-X.Y.Z.txt` (it
becomes the CTAN announcement via `l3build upload`), and re-run
`l3build doc` to refresh the typeset PDFs.

The CTAN archive is flat and carries exactly one `README.md` and one
`CHANGELOG.md`, both from the bundle root.

### Tests outside l3build

`numodel/tests/` contains a separate Lua test suite that exercises
`numodel.lua` directly (no LaTeX run): flow detection, layout, the
model export API and the plain-text (Coachtaal) rendering.  Run via

```
texlua numodel/tests/run.lua            # all tests
texlua numodel/tests/run.lua plaintext  # one topic
texlua numodel/tests/run.lua plaintext --update   # rewrite snapshots
```

Use `--update` with a topic: without one it also rewrites the
snapshots of tests that currently fail.

`numodel-plot/tests/` holds the siunitx compatibility matrix.
`numodel-plot` drives siunitx through its code-level interface, and
its `scale-format=prefix` feasibility check reaches a few siunitx
internals behind `\cs_if_exist` guards — a renamed internal never
errors, the label just silently comes out in the `10^k` form.  The
only way to know a siunitx release is fine is to render against it,
which `l3build check` cannot do (it always uses the installed
siunitx).  `siunitx-matrix.sh` downloads each requested siunitx git
ref, builds its `.sty`, renders `siunitx-matrix.tex` against it and
diffs the labels with those from the installed siunitx:

```
cd numodel-plot/tests
bash siunitx-matrix.sh v3.3.8 v3.5.10 v3.6.0
```

Every version must come out identical.  Run it before each release,
and whenever siunitx releases.

Both are independent of the l3build regression tests in
`numodel/testfiles/` and `numodel-plot/testfiles/`.

### numodel-coach: the Coach template

`numodel-coach` writes CMA Coach 7 activities by filling in an empty
activity saved by Coach (the `.cma7` format is not documented).  That
empty activity is stored as Lua data in
`numodel-coach/numodel-coach-template.lua`, generated by

```
python3 numodel-coach/tools/gen_template.py \
    "coach-proef/0. Leeg model tekst.cmr7" \
    numodel-coach/numodel-coach-template.lua
```

The generator removes machine-specific data (the webcam name Coach
records) and CMA's sample instruction text.  Regenerate only when a new
Coach version requires it, and test the result in Coach.  Background,
format notes and design decisions: `coach-proef/PLAN.md` (Dutch).

## Layout

```
numodel-bundle/
  build.lua           bundle-level configuration (CTAN metadata, packaging)
  tagsetup.lua        single source of truth for release_tag/release_date
                      plus the update_tag function; dofile'd by all
                      build.lua's so `l3build tag` propagates everywhere
  README.md           user-facing overview (shown on CTAN and GitHub)
  DEVELOPMENT.md      this file (not shipped)
  CHANGELOG.md        one changelog for the whole bundle
  release-X.Y.Z.txt   CTAN announcement per release (not shipped)
  docs/               local reference PDFs, e.g. the Coach 7 manual
                      (not shipped)
  coach-proef/        numodel-coach background: PLAN.md, format notes,
                      prototype scripts and test files (not shipped)
  numodel/
    build.lua         module configuration
    numodel.dtx       documented source
    numodel.ins       DocStrip installer
    numodel.lua       hand-written Lua iteration backend (ships as-is)
    numodel-manual.tex
    examples/         showcase documents
    testfiles/        l3build regression tests (.lvt + .tlg)
    tests/            Lua-level unit tests (texlua run.lua)
  numodel-plot/
    build.lua         module configuration
    numodel-plot.dtx
    numodel-plot.ins
    numodel-plot-manual.tex
    examples/
    testfiles/
    tests/            siunitx compatibility matrix (bash siunitx-matrix.sh)
  numodel-coach/
    build.lua
    numodel-coach.dtx
    numodel-coach.ins
    numodel-coach.lua           Coach file writer (ships as-is)
    numodel-coach-template.lua  empty Coach activity as Lua data (generated)
    numodel-coach-manual.tex
    testfiles/
    tools/            gen_template.py: regenerates the template (not shipped)
```
