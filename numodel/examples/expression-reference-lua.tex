\section*{Flattening \texttt{math} into the rule environment}

The verbose \texttt{math.} prefix in front of every call is the main
cost of using raw Lua expressions in user-authored rules.  Lua lets
you eliminate it by handing the loaded expression its own
environment.  The pattern (Lua 5.3, the version embedded in LuaTeX):

\begin{verbatim}
local function make_env(vars)
  local env = {}
  for k, v in pairs(math) do env[k] = v end  -- sin, cos, pi, huge, ...
  setmetatable(env, { __index = vars })      -- model variables fall through
  return env
end

local function compile_rule(expr, env)
  local f, err = load("return " .. expr, "rule", "t", env)
  if not f then error(err) end
  return f
end
\end{verbatim}

The Euler integrator then evaluates each rule with no boilerplate on
the user's side:

\begin{verbatim}
local env = make_env(vars)
local f   = compile_rule("v + g * dt", env)  -- user-typed expression
vars.v    = f()                              -- vars.g, vars.dt via __index
\end{verbatim}

Three things to note.  First, copying \texttt{math} into \texttt{env}
once gives a direct table lookup for \texttt{sin}, \texttt{cos},
\dots; only model-variable reads pay the metatable hop, and only on
first access per step.  Second, the \texttt{"t"} mode flag on
\texttt{load} restricts the chunk to text (no precompiled bytecode),
a useful sandbox guarantee for user input.  Third, name collisions
matter: if a model variable is called \texttt{sin}, \texttt{log},
\texttt{pi}, etc., the math binding in \texttt{env} shadows it.  In
practice this is a non-issue (physics models do not name a stock
\texttt{sin}), but it is worth a sanity check at \texttt{register}
time.

The next table repeats the expression reference under this
assumption: the \texttt{math.} prefix is gone everywhere.  Entries
that were derived stay derived; \textsf{numodel} could also inject
named helpers for \texttt{sign}, \texttt{cot}, \texttt{csc},
\texttt{round}, etc.\ into \texttt{env} to make those native too,
but that is outside the standard library and not assumed here.

One subtlety worth flagging: in radian-mode trig, \texttt{deg} is the
\emph{function} \texttt{math.deg} (radians$\to$degrees), so the
constant ``\texttt{deg}'' for $\pi/180$ has to be spelled out as
\texttt{pi/180}.
